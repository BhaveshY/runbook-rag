Runbook API

Same retrieval and answer pipeline as the workspace. Download the OpenAPI schema.

Investigate an incident

POST /api/diagnose returns a complete diagnostic note, source passages, and timings. POST /api/diagnose/stream sends server-sent events: status, evidence, answer, or error. The stream sends evidence first; it buffers the answer until exact-quote validation and a separate citation-support review finish. Unsupported claims and checks are removed. Review failure returns an error. 

curl http://localhost:8000/api/diagnose \
  -H 'Content-Type: application/json' \
  -d '{"query":"My pod is stuck in ImagePullBackOff. What should I inspect?","mode":"reranked"}'

Queries: 8–4,000 characters. Modes: reranked (default), hybrid, dense, bm25. Context k: 3–10 (default 8). Embeddings run on the server. Answer generation calls an OpenAI model through the Codex CLI or the OpenAI API. Never put an OpenAI key in a browser request.

Search without generation

POST /api/search accepts the same body and returns source passages plus the retrieval trace. BM25 search makes no model API request. Semantic and hybrid search use an embedding; reranked search adds a model call.

GET endpoint Returns
/api/health Index readiness, credential-presence flag, and access-token requirement. It does not probe the provider.
/api/corpus Corpus hash, source revision, document list, and embedding configuration.
/api/benchmark The committed benchmark report, including individual cases and failures, with a compatibility check against the running code, corpus, dataset, and model configuration.
/openapi.json Machine-readable endpoint definitions.

Access and failure handling

If the operator sets RUNBOOK_ACCESS_TOKEN, POST requests require Authorization: Bearer <instance-token>. This is a separate application token, not the OpenAI key. Public corpus metadata and benchmark results remain readable.

401: missing instance token. 408: body upload exceeds 10 seconds. 413: body exceeds 16 KiB. 422: invalid query or mode. 429: per-peer rate limit or process request budget reached. 503: index, provider, or evidence review unavailable. After a stream begins, failures arrive as an error event; clients must handle that event even though the HTTP status is 200.

Runbook displays commands and never runs them, and it stores no query text. The server sends incidents and retrieved documentation to OpenAI, through the Codex CLI or the OpenAI API. With the API, it disables response storage. OpenAI's retention policy still applies.
